# Preprocessing closeout failure expectations

Record these before implementation. Existing E2Es exercise fixed default caps,
valid dated gas rows and single-row catalogue summaries. They cannot expose
resource-policy fallback, stale pilot coverage, undated matched-record transport,
or compensating count errors across encounters without added fixtures. Extend
retained E2Es; do not substitute these synthetic checks for private acceptance.

- Requested limits/threads must reach staging, independent comparison, workers,
  parent/global validation and reference comparison. Effective settings are
  retained. Invalid values fail before private reads. Changed policy invalidates
  operational reuse and a pilot with absent/different coverage is rejected.
- One/two workers preserve both variants and exact independent row oracles; the
  controller-death lock fixture continues to hold the shared lock in workers.
- Exact source projections retain conflicting starts, repeated patients, undated
  or invalid matched values, raw units and provenance. Zero matches, unavailable
  fields/domain and failed/incomplete queries must remain distinguishable.
  Adjusted PCO2 stays distinct; duplicate memberships do not multiply rows.
- Catalogue counts must reconcile per encounter, including absent-summary NULL
  and present-summary unmatched zero. A pair of compensating errors cannot pass
  solely because totals agree.
- Validation initializes scratch before nested report creation. Success and
  actual failure both write a report with the established shape and exit code.
